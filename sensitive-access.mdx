BrowserPair observes pages through the extension in your connected Chrome profile. Protected fields are masked in Standard mode by default. Connecting an AI agent does not automatically disclose passwords, codes, card numbers or tokens.

## Protected categories

<CardGroup cols={2}>
  <Card title="Passwords" icon="lock">Passwords, passcodes and similar authentication values.</Card>
  <Card title="Verification codes" icon="mobile-screen">One-time and verification values.</Card>
  <Card title="Payment details" icon="credit-card">Card numbers and other payment-sensitive fields.</Card>
  <Card title="API keys and tokens" icon="key">API credentials, access tokens and other secrets.</Card>
  <Card title="Other protected data" icon="shield">Additional fields identified as sensitive.</Card>
</CardGroup>

## Requesting protected data

The task agent requests a single `sensitive_category` in an authorized observation. The account-wide **Permissions → Passwords and secrets** ask-before switch determines whether that observation needs your approval. Standard asks by default; Developer starts with the switch off. Browser identity, task intent, Chrome policy and required task confirmations still apply.

<Warning>
  The previous **Once / Task / Agent** reusable grants and per-agent Developer timers are not part of the current Permissions interface. Do not follow old per-key grant instructions.
</Warning>

## Manual steps remain yours

When a website requires sign-in, verification, a payment review or a local file choice, BrowserPair can pause for you to complete that step. Neither mode bypasses required manual input or permits blind replay of an uncertain effect.

See [Permissions](/permissions), [Developer mode](/developer-mode) and [Browser sessions and data flow](/browser-session-data-flow).
