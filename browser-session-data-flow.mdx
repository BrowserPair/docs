BrowserPair runs website interactions through the extension in your paired Chrome profile. The profile keeps its existing website sessions. BrowserPair also uses a cloud coordination service, and task observations can be returned to the AI app or model doing the planning.

## What stays in the browser

You pair the Chrome profile you want to use. BrowserPair's normal connection path does not require exporting a cookie file or uploading a browser profile to an AI app. The extension performs browser interactions in that profile.

An existing login is useful for authenticated work, but it is not a guarantee that every task will stay signed in. A website may require a fresh login or another human check.

## What can leave the browser

BrowserPair can provide observations and results needed to plan, execute, or verify a task. Depending on the task and its permissions, context can include page text, accessibility or DOM information, screenshots, and task results. The paired browser is therefore not a promise that all processing stays on your computer.

| Component | Role |
| --- | --- |
| Your Chrome profile and extension | Hold the website session and perform browser interactions. |
| BrowserPair service | Coordinates authorized task requests and durable task state. |
| Connected AI app, such as ChatGPT or Claude | Plans the external-agent workflow and receives permitted tool observations and results. |
| Configured Agent Model or Decision Model provider | Provides model processing for managed tasks when that path is configured. |

Review account-wide Permissions and current task context with the private data on the page in mind. Read the [privacy policy](https://browserpair.com/privacy) and the AI provider's own policies before using private accounts.

## Two planning paths

**Connected AI app:** connect [ChatGPT](/chatgpt), [Claude](/claude), or another compatible MCP client. That app provides the planning. You do not need to configure a managed Agent Model inside BrowserPair.

**Managed task:** configure an Agent Model in BrowserPair and run the task there. [Agent Model + Decision Model](/agent-decision-model) describes the model roles and provider routing.

Both paths use BrowserPair's task authority controls. A model's request or text found on a website cannot silently expand the task's allowed scope.

## Permissions and pauses

Choose the intended browser and task carefully, then set the account-wide Permissions ask-before switches. Review protected-data requests and required approvals rather than assuming that being signed in authorizes every action.

A task may pause when it needs permission, user input, or verification. When an action's effect is uncertain, inspect the task and current page state before retrying. A reconnect or repeated prompt should not be treated as proof that the previous action failed.
