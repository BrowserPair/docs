BrowserPair separates task planning and optional bounded model decisions from browser execution. A model may choose the next action, but only BrowserPair's connected Chrome executor can perform it, subject to live account permissions and task authority.

<Note>
  ChatGPT, Claude, and other connected AI apps provide their own models. You do not need to configure an Agent Model or Decision Model in BrowserPair to use them. This page is for tasks started inside BrowserPair.
</Note>

<CardGroup cols={3}>
  <Card title="Agent Model" icon="brain">Plans, evaluates uncertainty, chooses subgoals, and decides when richer context is needed.</Card>
  <Card title="Decision Model" icon="bolt">Optionally selects bounded operations and targets when effective confidence meets your threshold. It never executes browser actions or grants permissions.</Card>
  <Card title="Authority layer" icon="shield">Task and user permissions remain in force regardless of which model makes a decision.</Card>
</CardGroup>

## How the Agent Model works with your browser

BrowserPair creates a durable task before your configured Agent Model chooses a step. The Agent Model receives bounded browser observations and task tools, just as a connected MCP client does. Every step still follows the current account Permissions, immutable task confirmations, live refs and Chrome policy. The optional Decision Model can select operations for a bounded subgoal, but the browser executor performs them after all live security checks.

Your Agent Model can request one action, request a fresh observation or ask you a question. Replies in BrowserPair Chat provide context, **not** new permissions. Review ongoing work and verified or needs-review outcomes in **Activity**. An action with an unknown effect is never automatically replayed.

See [Managed tasks](/managed-tasks), [Remote MCP](/remote-mcp) and [Task semantics](/task-semantics).

## Supported provider types

| Provider | Agent Model | Decision Model | Configuration |
| --- | --- | --- | --- |
| Anthropic | Yes | Yes | Model ID + credential |
| OpenAI | Yes | Yes | Model ID + credential |
| Google | Yes | Yes | Gemini model ID + credential |
| TypeSafe | No | Yes | Decision Model only |
| OpenAI-compatible | Yes | Yes | HTTPS endpoint + model ID + credential |

<Note>BrowserPair stores provider credentials securely. The raw credential is not returned after creation.</Note>

## Configure routing

<Steps>
  <Step title="Add a provider">In the BrowserPair App, open **Settings → Models**, and select **Connect a model**. The first Agent Model you connect becomes the account default for tasks started within BrowserPair.</Step>
  <Step title="Choose primary and fallback">Set a default Agent Model and optional fallbacks.</Step>
  <Step title="Set Decision Model confidence">Below the threshold, BrowserPair escalates rather than guessing.</Step>
  <Step title="Review observation policy">Control accessibility, DOM, screenshot, or combined observations.</Step>
  <Step title="Keep bounded limits">Use safe defaults unless a workflow actually needs more room.</Step>
</Steps>

## Execution and permissions

The Agent Model plans and the Decision Model may choose a bounded action, but neither model can directly control Chrome or bypass BrowserPair. The extension executor enforces the account's current Standard or Developer permission settings, the task's site and action scope, Chrome website access, ownership and result verification. In Standard mode, sensitive operations can pause for a user decision as configured. Developer mode follows the user's current account policy; choosing a model does not change it. Unknown effects are not automatically retried.
