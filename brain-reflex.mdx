BrowserPair separates **planning** from **fast bounded execution** so routine browser work can stay responsive without giving the execution layer unlimited authority.

<Note>
  ChatGPT, Claude, and other connected AI apps provide their own models. You do not need to configure Brain or Reflex in BrowserPair to use them. This page is for tasks started inside BrowserPair.
</Note>

<CardGroup cols={3}>
  <Card title="Brain" icon="brain">Plans, evaluates uncertainty, chooses subgoals, and decides when richer context is needed.</Card>
  <Card title="Reflex" icon="bolt">Executes routine verified actions while effective confidence remains above your threshold.</Card>
  <Card title="Authority layer" icon="shield">Task and user permissions remain in force regardless of which model makes a decision.</Card>
</CardGroup>

## Your model works like an MCP client

The Brain you connect gets the same tools that ChatGPT or Claude get over [Remote MCP](/remote-mcp): `task_click`, `task_fill`, `task_navigate`, `task_adopt_tab`, `task_done` and the rest, limited to what the task may do, plus `task_observe` and `ask_user`. BrowserPair has already started the task, so the Brain never calls `browser_run` or `task_state`.

- **One step per turn.** On each turn the Brain sends a short message and one tool call. BrowserPair checks and runs the call exactly as it would an MCP call, with the same permissions, approvals and effect safety.
- **Refused steps.** If a call is refused before anything happens (an unknown element, invalid arguments, a missing permission), the Brain gets BrowserPair's guidance and can try another way. After three refusals on the same page, the task waits for you.
- **Questions.** When the request needs something only you know, such as your name or which plan to pick, the Brain asks with `ask_user` instead of guessing. The task waits until you answer.
- **Finishing.** The Brain finishes with `task_done` and criteria the page proves, so the result is recorded as verified. When it cannot finish, it uses `task_blocked`.

### The conversation

Every task run by your model has a conversation: your request, the model's messages and questions, and one line per browser step. You see it in the BrowserPair side panel and in the task details in the App. In either place you can answer a question or add an instruction while the task runs.

Your replies are your own words, just like the task request. They never grant permissions: the next step is checked like every other. The stored conversation is encrypted. It holds BrowserPair's own wording, the model's messages and the tool calls, never page text, typed values or file contents.

<Note>
  For OpenAI reasoning models (gpt-5, o-series), BrowserPair uses the model's own sampling settings when the model does not accept `temperature`.
</Note>

## Supported provider types

| Provider | Brain | Reflex | Configuration |
| --- | --- | --- | --- |
| Anthropic | Yes | Yes | Model ID + credential |
| OpenAI | Yes | Yes | Model ID + credential |
| Google | Yes | Yes | Gemini model ID + credential |
| TypeSafe | No | Yes | Reflex-only |
| OpenAI-compatible | Yes | Yes | HTTPS endpoint + model ID + credential |

<Note>Provider credentials are encrypted in BrowserPair Cloud. The raw credential is not returned after creation.</Note>

## Configure routing

<Steps>
  <Step title="Add a provider">In the BrowserPair App, open **Settings → Models**, and select **Connect a model**. The first Brain you connect becomes the account default.</Step>
  <Step title="Choose primary and fallback">Set a default Brain and optional fallbacks.</Step>
  <Step title="Set Reflex trust">Below the threshold, BrowserPair escalates rather than guessing.</Step>
  <Step title="Review observation policy">Control accessibility, DOM, screenshot, or combined observations.</Step>
  <Step title="Keep bounded limits">Use safe defaults unless a workflow actually needs more room.</Step>
</Steps>
